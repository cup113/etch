# ADR-0002: 单设备本地优先，v1 不做任何同步

牌桌上的真实习惯是一部手机躺在桌子中间或由一人当"刻工"。我们决定 v1 是**纯前端离线应用**：数据全部存本设备 IndexedDB，无后端、无账号、无局域网/云同步；跨设备迁移的唯一通道是**拓片（Rubbing）**——单块碑的版本化 JSON 导出/导入。部署因此是纯静态产物 + PWA（断网可开、可装主屏），任何静态宿主都能放。

## Considered Options

- 局域网多设备实时同步——需要服务发现、消息通道与冲突策略，工作量翻倍以上。
- 云同步 + 账号——与"轻、利落、离线"的产品气质相反。

## Consequences

- "永不消失"的承诺边界 = 本设备存储 + 用户手里的拓片；UI 必须让这个边界可见（IDB 不可用时显著提示"临时碑"）。
- 多标签页同时刻同一块碑 = 后写覆盖，接受为已知风险（单设备假设下几乎不会发生），不做同步机制。
- 追加式账本（ADR-0001）为将来接入同步留了路：笔是天然的操作单元。
- **缓存策略不是自由选择**：导航必须 network-first，只有内容寻址的构建产物走 cache-first。曾经让导航也走 cache-first，结果新部署永远进不来，旧页面继续请求已被删除的旧哈希 chunk，整站在线状态都打不开——离线能力反而把应用锁死在旧版本上。
- 离线能力从**第二次导航**起生效（首次访问的文档是被 service worker 中途 `clients.claim()` 接管的，其子资源请求不会经过 SW）。这是 PWA 的通行约定，e2e 按此断言。
- IndexedDB 拒绝克隆 Svelte 的响应式 Proxy（`DataCloneError`），落盘前必须 `$state.snapshot`；且要先写盘、再让 UI 可见，否则刷新会看到"界面上有分、库里没有"。
