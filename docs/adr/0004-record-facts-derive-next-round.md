# ADR-0004: 记桌面事实，推下一局开局

双升与掼蛋都要「封盘继续」：用户停下来、过几天再开，得立刻知道谁做庄、谁向谁进贡。但这些信息原先没有记——双升只记队，掼蛋只记胜队 + 同伴名次；下一局只能靠人记，封盘即丢。

我们决定：**把一局的桌面事实记进这一笔的 meta**（双升：本局庄家这个人；掼蛋：四人出完顺序），下一局的开局信息（庄家 / 进贡关系）**每次从全部未凿笔 + 变体 + 首庄推导**，不新增可变状态、不新增笔种。双升的「提前指定」作为上一笔的可选 `nextDeclarer`，仍然是追加式数据，凿除即回滚。优先级：本笔实际庄家 > 上一笔预指定 > 流转规则（轮庄 / 亮牌 / 指定）。进贡只到关系与规则提示（具体贡牌、还贡牌、抗贡结果不记账），因为那些是下一局发牌后才知道的桌面事实，记进来只会变成会过期的状态。

## Considered Options

- **在 `Game` 上放一个 `nextRound` 可变字段** —— 实现最省，但凿除、导入、改名都会让它变脏；违背「当前状态永远由账本推导」的模型。
- **新增一种「开局」笔专门记庄家 / 抗贡** —— 最灵活，但动到「非凿除笔至少一行」的核心不变量，也会让「第几刻」的编号多出一类无计分的笔。
- **把具体贡牌 / 还贡牌也记下来** —— 超出计分器的范围；而且这些牌下一局才出现，记在本局笔上必然过期。

## Consequences

- 下一局信息随凿除自动回滚；不需要迁移，也不需要「锁定 / 解封」这类状态。
- 旧碑 / 旧拓片仍可读：没有 `declarer` 的双升笔回落到「只知队」，没有 meta 的掼蛋笔不显示名次 / 进贡；拓片版本不变（纯增量字段）。
- 刻入表单必须收集这两件事实：双升的人、掼蛋的顺序；不再用会默默记错的一键默认值。
- 规则差异（亮牌后谁坐庄、双贡谁收大牌、抗贡）只作为提示 / 可选项，碑不执法。
